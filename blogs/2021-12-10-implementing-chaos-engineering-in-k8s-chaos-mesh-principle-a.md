<p><a class="" href="https://chaos-mesh.org/docs/" rel="noopener noreferrer" target="_blank">Chaos Mesh</a> is an open-source, cloud-native Chaos Engineering platform built on Kubernetes (K8s) custom resource definitions (CRDs). Chaos Mesh can simulate various types of faults and has an enormous capability to orchestrate fault scenarios. You can use Chaos Mesh to conveniently simulate various abnormalities that might occur in development, testing, and production environments and find potential problems in the system.</p>
<!-- -->
<p>In this article, I'll explore the practice of Chaos Engineering in Kubernetes clusters, discuss important Chaos Mesh features through analysis of its source code, and explain how to develop Chaos Mesh's control plane with code examples.</p>
<p>If you're not familiar with Chaos Mesh, please review the <a class="" href="https://chaos-mesh.org/docs/#architecture-overview" rel="noopener noreferrer" target="_blank">Chaos Mesh documentation</a> to get a basic knowledge of Chaos Mesh's architecture.</p>
<p>For the test code in this article, see the <a class="" href="https://github.com/mayocream/chaos-mesh-controlpanel-demo" rel="noopener noreferrer" target="_blank">mayocream/chaos-mesh-controlpanel-demo</a> repository on GitHub.</p>
<h2 class="anchor anchorTargetHideOnScrollNavbar_fkcC" id="how-chaos-mesh-creates-chaos">How Chaos Mesh creates chaos<a class="hash-link" href="https://chaos-mesh.org/blog/implement-chaos-engineering-in-k8s/#how-chaos-mesh-creates-chaos" title="Direct link to How Chaos Mesh creates chaos">​</a></h2>
<p>Chaos Mesh is a Swiss army knife for implementing Chaos Engineering on Kubernetes. This section introduces how it works.</p>
<h3 class="anchor anchorTargetHideOnScrollNavbar_fkcC" id="privileged-mode">Privileged mode<a class="hash-link" href="https://chaos-mesh.org/blog/implement-chaos-engineering-in-k8s/#privileged-mode" title="Direct link to Privileged mode">​</a></h3>

<p>The Linux capabilities grant containers privileges to create and access the <code>/dev/fuse</code> Filesystem in Userspace (FUSE) pipe. FUSE is the Linux userspace filesystem interface. It lets non-privileged users create their own file systems without editing the kernel code.</p>
<p>According to <a class="" href="https://github.com/chaos-mesh/chaos-mesh/pull/1109" rel="noopener noreferrer" target="_blank">pull request #1109</a> on GitHub, the <code>DaemonSet</code> program uses cgo to call the Linux <code>makedev</code> function to create a FUSE pipe.</p>

<p>When Chaos Controller Manager sends commands to Chaos Daemon, it creates a corresponding client based on the Pod information. For example, to control a Pod on a node, it creates a client by getting the <code>ClusterIP</code> of the node where the Pod is located. If the Transport Layer Security (TLS) certificate configuration exists, Controller Manager adds the TLS certificate for the client.</p>
<p>When Chaos Daemon starts, if it has a TLS certificate it attaches the certificate to enable gRPCS. The TLS configuration option <code>RequireAndVerifyClientCert</code> indicates whether to enable mutual TLS (mTLS) authentication.</p>

<h3 class="anchor anchorTargetHideOnScrollNavbar_fkcC" id="io-fault-injection">I/O fault injection<a class="hash-link" href="https://chaos-mesh.org/blog/implement-chaos-engineering-in-k8s/#io-fault-injection" title="Direct link to I/O fault injection">​</a></h3>
<p><a class="" href="https://github.com/chaos-mesh/chaos-mesh/pull/826" rel="noopener noreferrer" target="_blank">Pull request #826</a> introduces a new implementation of IOChaos, without the use of sidecar injection. It uses Chaos Daemon to directly manipulate the Linux namespace through the underlying commands of the <a class="" href="https://github.com/opencontainers/runc" rel="noopener noreferrer" target="_blank">runc</a> container and runs the <a class="" href="https://github.com/chaos-mesh/toda" rel="noopener noreferrer" target="_blank">chaos-mesh/toda</a> FUSE program developed by Rust to inject container I/O chaos. The <a class="" href="https://pkg.go.dev/github.com/ethereum/go-ethereum/rpc" rel="noopener noreferrer" target="_blank">JSON-RPC 2.0</a> protocol is used to communicate between toda and the control plane.</p>
<p>The new IOChaos implementation doesn't modify the Pod resources. When you define the IOChaos chaos experiment, for each Pod filtered by the selector field, a corresponding PodIOChaos resource is created. PodIoChaos' <a class="" href="https://kubernetes.io/docs/concepts/overview/working-with-objects/owners-dependents/" rel="noopener noreferrer" target="_blank">owner reference</a> is the Pod. At the same time, a set of <a class="" href="https://kubernetes.io/docs/concepts/overview/working-with-objects/finalizers/" rel="noopener noreferrer" target="_blank">finalizers</a> is added to PodIoChaos to release PodIoChaos resources before PodIoChaos is deleted.</p>

<h2 class="anchor anchorTargetHideOnScrollNavbar_fkcC" id="control-plane">Control plane<a class="hash-link" href="https://chaos-mesh.org/blog/implement-chaos-engineering-in-k8s/#control-plane" title="Direct link to Control plane">​</a></h2>
<p>Chaos Mesh is an open-source chaos engineering system under the Apache 2.0 protocol. As discussed above, it has rich capabilities and a good ecosystem. The maintenance team developed the <a class="" href="https://github.com/chaos-mesh/toda" rel="noopener noreferrer" target="_blank"><code>chaos-mesh/toda</code></a> FUSE based on the chaos system, the <a class="" href="https://github.com/chaos-mesh/k8s_dns_chaos" rel="noopener noreferrer" target="_blank"><code>chaos-mesh/k8s_dns_chaos</code></a> CoreDNS chaos plug-in, and Berkeley Packet Filter (BPF)-based kernel error injection <a class="" href="https://github.com/chaos-mesh/bpfki" rel="noopener noreferrer" target="_blank"><code>chaos-mesh/bpfki</code></a>.</p>
<p>Now, I'll describe the server side code required to build an end-user-oriented chaos engineering platform. This implementation is only an example—not necessarily the best example. If you want to see the development practice on a real world platform, you can refer to Chaos Mesh's <a class="" href="https://github.com/chaos-mesh/chaos-mesh/tree/master/pkg/dashboard" rel="noopener noreferrer" target="_blank">Dashboard</a>. It uses the <a class="" href="https://github.com/uber-go/fx" rel="noopener noreferrer" target="_blank"><code>uber-go/fx</code></a> dependency injection framework and the controller runtime's manager mode.</p>

<p>The control plane also needs to query and acquire Chaos resources, so that platform users can view all chaos experiments' implementation status and manage them. To achieve this, we can call the <code>REST</code> API to send the <code>Get</code> or <code>List</code> request. But in practice, we need to pay attention to the details. At our company, we've noticed that each time the controller requests the full amount of resource data, the load of the Kubernetes API server increases.</p>
<p>I recommend that you read the <a class="" href="https://zoetrope.github.io/kubebuilder-training/controller-runtime/client.html" rel="noopener noreferrer" target="_blank">How to use the controller-runtime client</a> (in Japanese) controller runtime tutorial. If you don't understand Japanese, you can still learn a lot from the tutorial by reading the source code. It covers many details. For example, by default, the controller runtime reads kubeconfig, flags, environment variables, and the service account automatically mounted in the Pod from multiple locations. <a class="" href="https://github.com/armosec/kubescape/pull/21" rel="noopener noreferrer" target="_blank">Pull request #21</a> for <a class="" href="https://github.com/armosec/kubescape" rel="noopener noreferrer" target="_blank"><code>armosec/kubescape</code></a> uses this feature. This tutorial also includes common operations, such as how to paginate, update, and overwrite objects. I haven't seen any English tutorials that are so detailed.</p>

<h3 class="anchor anchorTargetHideOnScrollNavbar_fkcC" id="orchestrate-chaos">Orchestrate chaos<a class="hash-link" href="https://chaos-mesh.org/blog/implement-chaos-engineering-in-k8s/#orchestrate-chaos" title="Direct link to Orchestrate chaos">​</a></h3>
<p>The container runtime interface (CRI) container runtime provides strong underlying isolation capabilities that can support the stable operation of the container. But for more complex and scalable scenarios, container orchestration is required. Chaos Mesh also provides <a class="" href="https://chaos-mesh.org/docs/define-scheduling-rules/" rel="noopener noreferrer" target="_blank"><code>Schedule</code></a> and <a class="" href="https://chaos-mesh.org/docs/create-chaos-mesh-workflow/" rel="noopener noreferrer" target="_blank"><code>Workflow</code></a> features. Based on the set <code>Cron</code> time, <code>Schedule</code> can trigger faults regularly and at intervals. <code>Workflow</code> can schedule multiple fault tests like Argo Workflows.</p>
<p>Chaos Controller Manager does most of the work for us. The control plane mainly manages these YAML resources. You only need to consider the features you want to provide to end users.</p>
